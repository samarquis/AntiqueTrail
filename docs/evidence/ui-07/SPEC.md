# UI-07 trip planning, Go, and collaboration review — spec

This spec is the implementation contract for the UI-07 evidence review. It
proves the private trip slice of the SLM-01 checkpoint: separate-account trip
planning, manual Review Hours, Trip → Partner → Navigator handoff, external-map
Go, and private visit memory. It follows the UI-06 spec and evidence README
patterns (`e2e/ui06-candidate-flows.spec.ts`,
`docs/evidence/ui-06/README.md`).

> **Disclaimer**: This harness runs on **synthetic in-memory data** generated by
> `src/review-harness/`. No real store, real email, real route, or real external
> map is contacted. Every identity below is a review-harness identity, not a
> person.

## Routes under review

All trip routes are behind `GuardedTrips` (`RequireSession`). Trip data access
is additionally denied at the client level to every non-Shopper role.

| Route | Component | Purpose |
| --- | --- | --- |
| `/trips` | `TripsPage` | Private trip list (the "My Trip" nav target) |
| `/trips/new` | `NewTripPage` | Create a draft trip |
| `/trips/:tripId/plan` | `PlanPage` | Order stops, review hours, offline queue |
| `/trips/:tripId/invite` | `InviteTripPartnerPage` | One partner + Navigator assignment |
| `/trip-invitations` | `AcceptTripInvitationPage` | Accept via `#token=` fragment |
| `/trips/:tripId/go` | `GoPage` | Navigator-run stop tracking + map handoff |
| `/trips/:tripId/check-my-day` | `AuthoritativeCheckMyDayPage` | Hours-aware suggestion |
| `/trips/:tripId/summary` | `SummaryPage` | Completed record + Plan Again |

## Seeded fixture (shopper-a)

`tripClient` seeds trip-a only for `shopper-a`:

- **trip-a** "Avery's antique day", `localDate 2026-08-08`, state `draft`,
  version 3, `departureMinute 600` (10:00 AM).
- **stop-a** Blue Finch Curios — store, `must`, 60 min, `planned`, hours
  `verified` 10:00 AM–5:00 PM (600–1020).
- **stop-b** Cedar & Brass — store, `prefer`, 45 min, `planned`, hours `stale`
  9:00 AM–4:30 PM (540–990), warning "Hours were last verified more than 180
  days ago."
- Collaboration: creator Avery, `navigatorUserId` = shopper-a → shopper-a is the
  Navigator on the Go page.
- `TRIP_A_INVITATION_TOKEN = 'review-trip-invite-shopper-b'` is registered in
  every scenario's token map.

Shopper-b has **no** trips seeded; representative and administrator roles have
no trip access at all.

## Harness prerequisites (must land with the spec build)

1. **`playwright.review.config.ts`**: add `'ui07-trip-flows.spec.ts'` to
   `testMatch`.
2. **Positive partner acceptance (row 12)**: the harness must seed shopper-b's
   `tripClient` with the trip-a collaboration record (creator Avery, pending
   invitation `trip-a-invite-shopper-b`, `navigatorUserId` shopper-a) so
   `acceptInvitation('review-trip-invite-shopper-b')` succeeds and adds
   shopper-b as Trip Partner. The current isolation unit test ("keeps shopper-b
   trips isolated while allowing self-created trips" in `clients.test.ts`)
   asserts the rejection (`/trip unavailable/i`) and must be updated when the
   seed lands. Until then the row asserts the current honest fail-closed
   behavior (acceptance errors with the generic trip alert; no cross-account
   trip data). Do not weaken the cross-account assertion: shopper-b's trip
   **list** must stay empty until acceptance.

## Ordered review rows (run in order)

1. **Anonymous shoppers cannot open private trip routes.**
   Open `/trips`, `/trips/new`, `/trips/trip-a/plan`, `/trips/trip-a/invite`,
   `/trip-invitations`, `/trips/trip-a/go`, `/trips/trip-a/check-my-day`, and
   `/trips/trip-a/summary` — each with `?reviewAs=anonymous`. Expect every route
   to redirect to `/auth/sign-in?returnTo=...` with no private trip content.

2. **The shopper-a trip list shows the seeded draft with its date.**
   Open `/trips?reviewAs=shopper-a&reviewState=success`. Expect heading
   "My trips", a **New trip** link, and one row in the "My trips" list:
   **Avery's antique day — 2026-08-08**, linking to `/trips/trip-a/plan`.

3. **Shopper-b has no trips and sees the honest empty state.**
   Open `/trips?reviewAs=shopper-b&reviewState=success`. Expect "No trips yet."
   and no "Avery's antique day" anywhere.

4. **A new trip is created and opens its plan.**
   On `/trips/new?reviewAs=shopper-a`, fill **Trip name** ("River walk") and
   **Date** (2026-08-15), then **Create trip**. Expect navigation to
   `/trips/trip-1/plan` with "River walk" as the page heading.

5. **The plan renders both seeded stops with hours and stale-data honesty.**
   Open `/trips/trip-a/plan?reviewAs=shopper-a`. Expect heading "Avery's antique
   day" and "Trip date: 2026-08-08". In the **Ordered trip stops** list:
   - Blue Finch Curios — must, 60 minutes, planned, with "Trip-date hours:
     10:00 AM–5:00 PM."
   - Cedar & Brass — prefer, 45 minutes, planned, with the stale warning
     "Hours were last verified more than 180 days ago."
   No feasibility, travel-time, or optimal-order claim appears anywhere.

6. **Plan interactions update the draft.**
   On `/trips/trip-a/plan`:
   - Rename to "Avery's revised day" → heading updates.
   - Move **Cedar & Brass** up → list order swaps; **Move Up** is disabled on
     the first stop and **Move Down** on the last.
   - Change Cedar & Brass **Priority** to `Must` and its **Dwell minutes** to 60
     (blur) → row reflects both.
   - **Remove** Blue Finch Curios → row disappears.
   - Add stop "River walk café" (Prefer, 30) → new row appears.
   - Restore the two seeded stops via **Add stop** (Blue Finch Curios, Must, 60;
     Cedar & Brass, Prefer, 45) so later rows stay deterministic.

7. **Review Hours stays honest with an unresolved stale warning.**
   On `/trips/trip-a/plan`, choose **Review Hours**. Expect the generic
   private-data alert "We couldn't update this trip. Please try again." — the
   harness refuses to acknowledge the unresolved Cedar & Brass warning silently
   — and never a route-feasibility claim.

8. **Offline queue: queue, replay to conflict, resolve.**
   On `/trips/trip-a/plan`, choose **Save a change offline**. Expect
   "1 change queued offline. Reconnect to replay them." Choose **Replay queued
   changes**. Expect the conflict alert "A queued action no longer applies."
   with **Keep This Phone's Version** and **Keep Saved Version**. Choose
   **Keep Saved Version** → the conflict clears. Alternatively choose **Purge
   offline copy** → "Offline data was purged. Reconnect before making another
   change."

9. **Go: Navigator starts the trip and tracks stops to completion.**
   Open `/trips/trip-a/go?reviewAs=shopper-a`. Expect heading "Go", the manual
   description, and **Start trip** (shopper-a is the Navigator). After start:
   - "Navigate to current stop" shows the stop address with **Open in Google
     Maps** (`google.com/maps/search/?api=1&query=...`) and **Open in Waze**
     (`waze.com/ul?q=...&navigate=yes`).
   - **Skip** Blue Finch Curios → state `skipped`, then **Undo skip** → back to
     `planned` (restore works for skipped stops).
   - **Arrived** → **Done** completes Blue Finch Curios; the private
     **VisitMemoryForm** appears (rating / return / note), saving shows
     "Private memory saved." and the form disappears.
   - Complete Cedar & Brass the same way. When every stop is terminal the trip
     auto-completes and navigates to the summary.

10. **Summary shows the completed record and supports Plan Again.**
    On `/trips/trip-a/summary?reviewAs=shopper-a` (arrived via the Go journey):
    expect "Avery's antique day — completed", "Visited: 2 · Skipped: 0 ·
    Appeared closed: 0 · Duration: 2 hr", "Blue Finch Curios: Visited —
    Private memory saved", "Cedar & Brass: Visited — Private memory missing",
    and **Plan Again**. Choose **Plan Again** → navigates to a new plan titled
    "Avery's antique day (copy)".

11. **Check My Day suggests an order from reviewed hours only.**
    Open `/trips/trip-a/check-my-day?reviewAs=shopper-a`. Choose **Check My
    Day**. Expect a **Suggested order** section with the explanation and
    **Use Suggested Order** / **Keep My Order** choices. Choose **Use Suggested
    Order** → no error; the trip reorders to the suggested stop ids
    (must first, then earlier opening). The copy never claims travel time or
    route feasibility.

12. **Partner invitation and acceptance.**
    - On `/trips/trip-a/invite?reviewAs=shopper-a`: expect "Trip Partner and
      Navigator", participant "Avery — creator — Navigator", the invite form,
      and a pending-invitation block after sending
      `shopper-b@local.invalid` ("One invitation is pending until …" with
      **Revoke invitation**).
    - Acceptance (harness prerequisite 2): open
      `/trip-invitations?reviewAs=shopper-b&reviewState=success#token=review-trip-invite-shopper-b`
      and expect "You joined this one trip as Trip Partner." with **Open shared
      trip**. The token fragment follows the real query string (query before
      `#hash`). Until the fixture change lands, this resolves to the generic
      private-data alert with no shopper-a trip content — the honest fail-closed
      row, documented by the "keeps shopper-b trips isolated while allowing
      self-created trips" unit test (`clients.test.ts`).

13. **Loading, empty, error, blocked, and permission-denied states stay honest.**
    - `/trips?reviewAs=shopper-a&reviewState=loading` → "Loading…"
    - `/trips?reviewAs=shopper-a&reviewState=empty` → "No trips yet."
    - `/trips?reviewAs=shopper-a&reviewState=error|blocked|permission-denied` →
      the generic trip alert; no fabricated trip rows.
    - `/trips/trip-a/plan?reviewState=error` → "Trip unavailable" card with the
      generic alert.
    - `/trips/trip-a/go?reviewState=error` → "Go unavailable" card with the
      generic alert.

14. **Cross-account access is denied.**
    Open `/trips/trip-a/plan?reviewAs=shopper-b` and
    `/trips/trip-a/go?reviewAs=shopper-b`. Expect the loading-only plan/go cards
    ("Trip plan … Loading your private trip…", never "Avery's antique day" or
    stop rows) — shopper-b's client resolves the other account's trip to
    nothing.

15. **Cross-role access is denied.**
    Open `/trips?reviewAs=representative` and `/trips?reviewAs=administrator`.
    Expect the generic trip alert, never a trip row or "No trips yet." (the
    client denies the role before any list).

16. **200% reflow at 320 CSS px.** Set the window to 320 px wide; the trip plan
    page remains usable with no horizontal overflow.

17. **Actionable targets meet the 48 × 48 px baseline.** On `/trips`,
    `/trips/new`, `/trips/trip-a/plan`, `/trips/trip-a/invite`,
    `/trips/trip-a/go`, `/trips/trip-a/summary`, `/trips/trip-a/check-my-day`,
    and `/trip-invitations`, no actionable target is smaller than 48 × 48 px.

## Automated evidence

`e2e/ui07-trip-flows.spec.ts` asserts every row above against the harness in
serial mode, on desktop, tablet, and mobile viewports:

```powershell
# one terminal: the harness dev server
npm run dev:review -- --host 127.0.0.1 --port 4174

# second terminal: run the review suite
npx playwright test --config=playwright.review.config.ts ui07-trip-flows
```

To also write the approved viewport screenshots (used for dated evidence):

```powershell
$env:CAPTURE_UI07_EVIDENCE='true'
npx playwright test --config=playwright.review.config.ts ui07-trip-flows
```

Screenshots land in `docs/evidence/ui-07/{project}-{slug}.png` for the six
evidence viewports (trip list, trip plan, go, summary, invite/partner,
check-my-day). The Go viewport is captured after **Start trip** so the
navigator controls and map handoff links are visible; the summary viewport
captures the completed record.

After the automated run passes, the evidence README
(`docs/evidence/ui-07/README.md`) is written with the ordered rows, the
acceptance matrix marked ☑, the reproduce commands, and the dated screenshot
table — matching `docs/evidence/ui-06/README.md`.
