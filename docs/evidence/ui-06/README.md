# UI-06 candidate capture, shares, and trip ideas review

This review proves the private Candidate Link → Candidate Share → Trip Idea
flows required by the SLM-01 checkpoint: an authenticated shopper captures a
candidate link privately, sends it to one named recipient, and the recipient
accepts, dismisses, blocks, reports, or revokes it without any cross-account
access to private data.

> **Disclaimer**: This harness runs on **synthetic in-memory data** generated by
> `src/review-harness/`. No real store, real email, or real external link is
> contacted. Every identity below is a review-harness identity, not a person.

## Start the review harness

```powershell
# terminal 1 — the harness dev server (Vite, review env)
npm run dev:review -- --host 127.0.0.1 --port 4174
```

Open `http://127.0.0.1:4174/review` and verify the harness home lists the
shopper, representative, and administrator identities.

Every step below is a URL with `?reviewAs={identity}&reviewState={state}`.
The harness renders each identity's private state fresh per page load.

## Ordered review steps (run in order)

1. **Anonymous shoppers cannot open private candidate routes.**
   Open `/capture?reviewAs=anonymous`, then `/shares?reviewAs=anonymous`,
   `/trip-ideas?reviewAs=anonymous`, and
   `/account/privacy/blocked-senders?reviewAs=anonymous`.
   Expect each to redirect to `/auth/sign-in?returnTo=...` with no private
   content rendered.

2. **The shopper-b inbox lists every share with direction and state.**
   Open `/shares?reviewAs=shopper-b&reviewState=success`.
   Expect four rows:
   - Weekend estate-sale lead — received · pending
   - Antique sideboard lead — received · closed (expired)
   - Vintage lamp lead — received · closed (revoked)
   - Mid-century credenza lead — sent · pending

   An expired share resolves as closed, matching production: a pending share
   whose expiry has passed is unreadable and unclaimable immediately
   (PRODUCT_DECISIONS.md 103 / PRD 375).

3. **Share details and actions differ by direction and state.**
   - `/shares/share-b?reviewAs=shopper-b` — received · pending; shows
     Accept, Dismiss, Block, and Report.
   - `/shares/share-expired?reviewAs=shopper-b` — received · closed; no
     Accept (expired shares cannot be claimed).
   - `/shares/share-revoked?reviewAs=shopper-b` — received · closed; no
     Accept.
   - `/shares/share-b-sent?reviewAs=shopper-b` — sent · pending; shows
     Revoke only.

4. **Accepting a share creates a private Trip Idea.**
   On `/shares/share-b?reviewAs=shopper-b` choose **Accept**. Expect the
   status to change to accepted. Return to the inbox, open **More**, then
   **Trip Ideas**; expect both the seeded idea (North Topeka finds) and the
   accepted share's idea (Weekend estate-sale lead) with the source share
   noted.

5. **Dismiss, block, report, and revoke close shares.**
   - Dismiss `/shares/share-b` → received · closed.
   - Block `/shares/share-b` → received · closed; then the inbox's
     **Manage blocked Candidate senders** link shows the sender's label
     (Weekend estate-sale lead) next to the seeded blocked sender.
   - Report `/shares/share-b` → received · closed.
   - Revoke `/shares/share-b-sent` → sent · closed and the Revoke action
     disappears.

6. **Trip Ideas edit with optimistic versioning and delete with confirmation.**
   On `/trip-ideas?reviewAs=shopper-b` choose **Edit**, change the idea
   title, and **Save changes**; expect the new title. A conflicting edit
   (stale version) is rejected. Choose **Delete** and confirm the prompt;
   expect the empty state.

7. **Blocked senders can be reviewed and unblocked.**
   On `/account/privacy/blocked-senders?reviewAs=shopper-b` expect the seeded
   blocked sender, choose **Unblock**, confirm, and expect the empty state.

8. **Capture validates, saves, and sends a candidate share.**
   On `/capture?reviewAs=shopper-a`:
   - Submit empty → native required validation, no app alert.
   - Paste `ftp://example.com/estate` → app rule alert
     "Enter an eligible HTTP or HTTPS link."
   - Paste `https://www.example.com/estate` with a private note → saved
     privately; extracted details are labeled unverified suggestions.
   - Enter an invalid recipient email → the send is held by native email
     validation.
   - Enter `shopper-b@local.invalid` → "Share sent. If the recipient can
     receive it, it will appear in their inbox."

9. **Keyboard-only acceptance.**
   On `/shares/share-b?reviewAs=shopper-b` focus **Accept** and press Enter;
   expect the share to become accepted with the action removed.

10. **Loading, empty, error, blocked, and permission-denied states stay honest.**
    - `/shares?reviewAs=shopper-b&reviewState=loading` → "Loading shares…"
    - `/shares?reviewAs=shopper-b&reviewState=empty` → "No pending shares."
    - `...&reviewState=error|blocked|permission-denied` → a private-data alert
      explaining the item could not be updated; no fabricated data.
    - `/trip-ideas?reviewAs=shopper-b&reviewState=empty` → empty state.

11. **200% reflow at 320 CSS px.** Set the browser window to 320 px wide at
    200% zoom; the shares inbox remains usable with no horizontal overflow.

12. **Cross-account access is denied.** Open
    `/shares/share-b?reviewAs=shopper-a`; expect a private-data alert, never
    shopper-b's share.

13. **Cross-role access is denied.** Open
    `/shares/share-b?reviewAs=representative` and
    `/shares/share-b?reviewAs=administrator`; expect the "This private area
    is unavailable" guard for each, never shopper data.

14. **Actionable targets meet the 48 × 48 px baseline.** On `/shares`,
    `/shares/share-b`, `/trip-ideas`, and `/capture`, no actionable target
    is smaller than 48 × 48 px.

## Reproduce the automated evidence

The Playwright suite asserts every row above against the harness, on desktop,
tablet, and mobile viewports:

```powershell
# one terminal: the harness dev server
npm run dev:review -- --host 127.0.0.1 --port 4174

# second terminal: run the review suite
npx playwright test --config=playwright.review.config.ts ui06-candidate-flows
```

To also write the approved viewport screenshots (used for dated evidence):

```powershell
$env:CAPTURE_UI06_EVIDENCE='true'
npx playwright test --config=playwright.review.config.ts ui06-candidate-flows
```

Screenshots land in `docs/evidence/ui-06/{project}-{slug}.png` for the six
evidence viewports (inbox, share details, outbox share, trip ideas, blocked
senders, capture).
