## Evidence, lifetime and recovery

### Substitute hosting and recovery acceptance

Before this exception may activate, its own receipt must pass all of the following; the operator records evidence and an independent reviewer checks the immutable candidate and receipt. Missing evidence blocks publication, rather than being described as an H-01 pass or deferred until after exposure.

1. Record dated free-plan eligibility, limits and hard no-spend behavior; exact project/team/backend identifiers, U.S. region, every hostname and generated/preview protection state; data flows, processor retention and credential custody/rotation. Prove anonymous access only to the intended public frontend, server-side denial of unadmitted private/privileged operations, and current quota/availability monitoring with a named stop owner.
2. Export a consistent recoverable set of the preserved beta database schema/data, Auth identities and relevant configuration, Storage metadata and object bytes, migration history, function versions and deployment configuration. Inventory all affected records/objects without publishing personal data or secrets. Encrypt exports with separately held recovery key material, record private locations and hashes, retention/deletion duties and operator access; verify decryption and digest integrity. Secret values are restored from protected custody or explicitly rotated, never placed in public evidence.
3. Restore that matching set into a task-owned isolated local target in the approved region or an explicitly approved isolated remote target. Never reset beta or another worker's database. Record exact version-pinned export/restore commands and prove schema, row/object counts and hashes, Auth/session admission and revocation behavior, private-data denial, function/config compatibility and any provider-specific recovery limits. A schema-only dump, empty reset or backup badge cannot pass this rehearsal. Do not send mail or activate restored accounts during the rehearsal. Keep registration closed until exact provider identity/cleanup/finality and applicable E-01 delivery proofs pass on the actual target.
4. Record the measured recovery time and acceptable data-loss window for this test, prove restoration within that recorded bound, and verify that the frontend can return to a compatible retained artifact or a tested maintenance/stop state without rebuilding. Rehearse the stop operation and rollback in isolation before activation; verify the retained deployed artifact identity and alias mapping on the provider. If historical provider-managed Auth or Storage behavior cannot be reproduced locally, identify and prove it against the preserved hosted target without destructive changes; do not replace that evidence with a local simulation.
5. Preserve the immutable acceptance receipt and private recovery set through the test lifetime, with explicit expiry, support/incident contact, quota/outage response and post-test retention/disposal instructions. Any failed recovery, unknown migration/provider state, expired receipt or inability to deny unsafe activity blocks new test admission and publication. Wider shared/public stages still require their original H-01 and dependent service receipts.
